# Task 19 - Persistencia segura de MFA

## Objetivo

Criar a modelagem Prisma e os servicos de dominio para desafios de e-mail, TOTP e codigos de recuperacao, com protecao de dados sensiveis.

## Tarefas

1. Criar migration Prisma para os dados de MFA vinculados ao usuario, contendo apenas o necessario para:
   - metodos MFA habilitados;
   - segredo TOTP protegido em repouso;
   - desafio de login pendente, expiracao e contador de tentativas;
   - codigo de e-mail com hash, expiracao e indicador de uso;
   - codigos de recuperacao com hash e indicador de uso;
   - auditoria minima de eventos sensiveis.
2. Criar funcoes de servico em `backend/src/services/` para iniciar, consultar, confirmar, ativar, desativar e invalidar dados de MFA.
3. Gerar codigos de e-mail alfanumericos com fonte criptograficamente segura, armazenando somente hash e metadados necessarios.
4. Aplicar expiracao curta, uso unico, limite de tentativas e intervalo minimo de reenvio. Invalidar qualquer desafio anterior quando um novo desafio for criado.
5. Gerar codigos de recuperacao de uso unico; exibi-los somente na ativacao ou renovacao autorizada e armazenar apenas hashes.
6. Proteger o segredo TOTP em repouso com mecanismo de criptografia definido na task 18. Nunca devolver o segredo em consultas rotineiras.
7. Criar schemas Zod para todos os payloads e validar ownership no servico com `userId` em todas as buscas e alteracoes.
8. Atualizar seed de forma idempotente, sem habilitar MFA automaticamente no usuario administrador.

## Regras

- Nunca registrar codigo, hash, segredo TOTP, token OAuth ou senha em logs, respostas ou excecoes exibidas ao usuario.
- Para recursos autenticados, nunca buscar somente por `id`; incluir `userId` no filtro.
- Acesso sem sessao deve retornar `401`; recurso sem ownership deve retornar `404`.
- Criar migration e executar `pnpm run db:generate` apos mudar o schema.

## Checklist

- [ ] Migration Prisma criada e aplicada no ambiente local.
- [ ] Segredos/codigos sensiveis nao ficam em texto puro.
- [ ] Codigos de e-mail expiram, nao podem ser reutilizados e respeitam limite de tentativas.
- [ ] Codigos de recuperacao sao exibidos uma vez e usados uma vez.
- [ ] Seed continua idempotente e sem MFA ativo por padrao.
- [ ] `pnpm run db:generate`, `pnpm run lint`, `pnpm run format:check` e `pnpm run typecheck` passam.
