# Task 22 - Testes e documentacao de MFA e Login Google

## Objetivo

Validar os fluxos de autenticacao reforcada e documentar a operacao local sem expor dados sensiveis.

## Tarefas

1. Criar testes unitarios para geracao e verificacao de codigo de e-mail, expiracao, uso unico, limite de tentativas, reenvio, TOTP e codigos de recuperacao.
2. Criar testes de integracao para os endpoints/adapters de desafio MFA, configuracao de fatores, revogacao e ownership por `userId`.
3. Criar testes de componente para login, desafio MFA e controles da secao Seguranca, incluindo estados de carregamento e erro.
4. Criar teste E2E do fluxo principal: login por e-mail/senha com MFA por e-mail; incluir cenarios de TOTP e login Google com mocks controlados quando os provedores externos nao estiverem disponiveis.
5. Testar manualmente a configuracao TOTP usando Google Authenticator ou aplicativo compativel e verificar que o codigo aceita a janela de tempo esperada sem aceitar reutilizacao indevida.
6. Atualizar README com variaveis de ambiente, callback OAuth, configuracao do remetente de e-mail, habilitacao de MFA, recuperacao de acesso e advertencia para nao versionar segredos.
7. Rodar as validacoes de qualidade e registrar resultados no PR/commit da implementacao.

## Criterios de aceite

- Usuario sem MFA entra normalmente com e-mail/senha.
- Usuario com MFA por e-mail conclui o login somente com codigo valido, nao expirado e nao reutilizado.
- Usuario com TOTP conclui configuracao com QR code e login com aplicativo compativel.
- Codigo de recuperacao funciona uma unica vez e gera auditoria sem vazar seu valor.
- Google OAuth funciona com configuracao valida e apresenta falha controlada sem configuracao ou em callback invalido.
- Segredos, tokens e codigos nao aparecem em testes, logs, respostas ou README.
- `pnpm run db:generate`, `pnpm run lint`, `pnpm run format:check`, `pnpm run typecheck` e `pnpm run build` passam, assim como a suite de testes adicionada.
