# Task 07 — Ajustes de base, env e separação de responsabilidades

> **Pré-requisito:** executar antes de qualquer task de APIs ou módulo de domínio.

---

## Objetivo

Corrigir a fundação do projeto antes de avançar para APIs e módulos de domínio, garantindo que:

- o projeto use somente `.env` e `.env.example` como arquivos de ambiente;
- regras de negócio, validação, acesso a dados e integrações externas vivam exclusivamente no backend;
- o frontend se limite a UI, navegação, estado de tela e chamadas HTTP;
- testes e validações reflitam e protejam essa separação.

## 1 · Ajustes de ambiente

Manter somente dois arquivos de env em `projeto/`:

```
projeto/.env          — execução local e Docker Compose
projeto/.env.example  — apenas placeholders; versionado no git
```

**Ações obrigatórias:**

- Remover `projeto/.env.local` e toda referência a ele em README, tasks e scripts.
- No Docker Compose, sobrescrever apenas as variáveis que precisam apontar para `db:5432`; não exigir arquivo extra de env.
- `projeto/.env.example` não pode conter segredos reais — somente credenciais fictícias de desenvolvimento.
- `projeto/.gitignore` deve ignorar `.env` e versionar `.env.example`.
- `docker-compose.yml`: `name: kwak-finance`, serviços `kwak_finance_app` / `kwak_finance_db`, volume com prefixo `kwak_finance_`.

## 2 · Separação backend / frontend

### Backend deve conter

- Prisma Client e acesso ao banco.
- Better Auth — configuração do servidor.
- Gemini via Vercel AI SDK e qualquer uso de `GOOGLE_GENERATIVE_AI_API_KEY`.
- Schemas Zod de domínio e payloads de API.
- Validações de negócio, incluindo datas com Day.js e CPF/CNPJ com biblioteca especializada.
- Parse e normalização de CSV Nubank.
- Cálculos financeiros usados por dashboard, transações, investimentos, metas e empresarial.
- Serviços de domínio em `projeto/backend/src/services/`.
- Tipos de domínio internos em `projeto/backend/src/types/`.

### Frontend pode conter

- Componentes visuais, layouts e páginas.
- Navegação e estado de tela.
- Formulários com validação de UX quando necessário.
- Clients HTTP ou actions finas que chamam API routes.
- Tipos/contratos de UI sem expor detalhes internos do banco.
- Formatadores puros de exibição (moeda, percentual, data).

### Frontend não pode conter

- Imports de `@prisma/client`.
- Imports de `@anthropic-ai/sdk`, `@ai-sdk/google` ou `ai`.
- Acesso a `process.env` com segredos do servidor.
- Regras de ownership, persistência ou cálculos financeiros de domínio.
- Parse definitivo de CSV Nubank quando o resultado for persistido.
- Categorias ou decisões de IA aplicadas diretamente no estado de UI sem validação prévia no backend.

- Route handlers em `projeto/frontend/src/app/api/**` são adapters finos: recebem a requisição HTTP, delegam para `projeto/backend/` e retornam a resposta. Não contêm lógica de domínio.

## 4 · Regras de implementação

- Proibido usar `any`.
- Prefira named exports em todos os módulos.
- Use Zod nos contratos de entrada do backend.
- Use Day.js para datas de entrada e regras de período.
- Moeda na UI: `Intl.NumberFormat("pt-BR", { style: "currency", currency: "BRL" })`.
- Datas na UI: formato `dd/MM/yyyy`.
- Componentes React não importam serviços de domínio, Prisma, SDKs de IA, secrets ou schemas internos de persistência.
